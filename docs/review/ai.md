### Medium Priority — No hydration-mismatch debugging recipe for known footgun

SSR/WASM hydration parity is one of this codebase's sharpest recurring hazards — feature-gating a component body on `web` makes SSR and WASM render different markup and the page silently mis-hydrates (blank page / flicker / dead handlers). It is serious enough to live in the operator's private memory ("never feature-gate component bodies on web; SSR and WASM must render identical markup"), and the architecture leans on it everywhere (view_prefs.rs SSR-defaults note line 73; the auth/ primitives "SSR/WASM identical for hydration" line 85). Yet no repo-checked-in agent doc gives a debugging recipe: no symptoms list, no root-cause list (feature-gated rsx, non-deterministic content like timestamps/random, SSR-only defaults differing from client state), no confirmation steps (`preview_console_logs`, compare SSR HTML vs hydrated DOM), no fix guidance. `grep -i hydrat` across CLAUDE.md/.claude/rules/architecture.md finds only descriptive mentions (architecture.md:73,85), never a procedure. An agent hitting a hydration bug while building the many UI-heavy roadmap features still ahead (reader, stats, shelves) has to rediscover the whole failure mode. Fix: add a short "Debugging hydration mismatches" section (in 05-rust-style or a dedicated rule) codifying the never-feature-gate-bodies invariant (currently only in private memory), the common causes, and the console-log/DOM-diff confirmation steps.
